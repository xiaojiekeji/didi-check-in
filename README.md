# didi-check-in

安卓端「滴滴出行 · 小桔充电」每日自动签到工具。纯本机运行，不联网上传任何数据，不需要抓包、不需要 token。

> 说明：本工程基于无障碍服务（AccessibilityService）模拟点击实现，属于对平台规则的灰区操作。
> 建议先用小号试运行 1~2 周，一天只跑一次，遇到验证码/滑块立即停手，不要做破解。

## 签名与覆盖安装（v1.5.3 起）

以前每次 GitHub Actions 构建都会现生成一把临时 debug key，签名每次不同 → 装新版本必须卸载旧版本（打卡记录、日志全丢）。

现在改为**仓库内固定签名**：

- keystore：`keystore/didi-check-in.p12`（PKCS12，别名 `didi`，密码 `didi2026checkin`，随仓库一起走，CI 每次都用它）
- `app/build.gradle` 里 `signingConfigs.didi` 同时挂在 `debug` 和 `release` 两个 buildType 上
- 证书 SHA-256：`58:3E:D8:A6:47:8F:DC:A3:BE:49:76:06:65:1B:EF:4D:67:11:EC:EA:BE:97:93:29:8A:71:FC:EB:52:00:E4:2C`
- CI 每次构建后会跑 `apksigner verify --print-certs`，把签名指纹打到 job summary 里，可自行核对是否一致

结果：从 v1.5.3 起的新包都可以**直接覆盖安装**（`adb install -r`），不需要先卸载。

> 唯一例外：从旧版本（随机签名的包）升级到 v1.5.3，必须**最后卸载一次**，因为签名对不上，系统会拒绝安装。卸载后打卡记录会清空，这一步只需要做一次。
>
> 注意：keystore 是跟着公开仓库走的，等于公开的签名密钥（性质接近当年 AOSP 那个公共 debug key）。风险是有人能做出同签名 APK 覆盖安装你的应用；如果介意，可把 keystore 换成 GitHub Actions Secret 存放，但那样 CI 需要额外配置。


## 功能

- 每天早上 **7:00~8:00** 之间自动触发（基准 07:00 + 0~60 分钟随机偏移），避开机械的整点特征
- 触发后自动**点亮屏幕**，若手机锁屏则尝试用锁屏密码（默认 `688888`）自动解锁；解不开会发通知，解锁后自动继续
- 开机、应用更新后自动恢复排程
- **截图 + OCR 文字识别 + 坐标点击**，不再依赖页面控件的文字节点（自绘 / H5 页面也能识别）
- 固定路线：打开 App → 关掉所有弹窗 → 顶部「车主」→ 关弹窗 → 「滴滴充电」→ 关弹窗 → 右下「我的」→ 「会员中心」→ 下滑找「签到」→ 点击 → 校验
- 校验失败自动重试（间隔 5 分钟，最多 3 次）
- 成功后自动截图存证，截图直接进「打卡记录」
- 本地日志（保留 30 天）、通知栏汇报结果
- 关键词全部放在资源文件里，页面改版只改 `arrays.xml`，不用改代码

## 识别方式（v1.2 起，v1.3 提速）

旧版靠无障碍读取控件文字，滴滴把页面改成自绘 / 图片渲染之后就读不到「签到」这两个字了。现在改成：

1. 用 `AccessibilityService#takeScreenshot` 抓当前屏幕（Android 11+ 免授权截图）
2. 交给 **ML Kit 中文离线 OCR**（模型打包进 APK，运行时完全离线、不联网）识别出所有文字行及其**屏幕像素坐标**
3. 按关键词在识别结果里匹配（完全相等 > 前缀 > 包含），拿到目标文字的中心点后 `dispatchGesture` 点击

Android 11 以下没有免授权截图能力，会自动降级为读取控件文字（功能可用性取决于目标页面是否暴露文字节点）。

### v1.3 的提速与防误点

最短路径：**打开滴滴 → 进「滴滴充电」→ 底部「我的」→「会员中心」→ 下滑 → 点「签到」→ 校验并截图**（不再绕「车主」这一跳，找不到充电入口时才自动回退到「车主」路径）。正常情况 5~10 秒跑完一轮。

- **只识别需要的那块屏幕**：找「我的」只看屏幕下半部分，找「会员中心」只看上半部分，签到页只识别中间 80%，比整屏识别快 2~3 倍，也少认错别处的文字
- **节奏从 1.2 秒压到 320 毫秒**：点完只等 320ms 就复检；没找到目标 240ms 后再看一眼；单阶段上限 8 秒，整轮上限 70 秒（原来 150 秒）
- **控件文字 + OCR 合并**：无障碍能读到的文字直接并进候选（几乎零成本），命中就点，减少反复识别
- **OCR 回调统一回主线程再点**：手势不再被后台线程排队拖慢

防「乱点跳到别的页面」：

- **不再「见 × 就点」**：只有屏幕上出现弹窗特征文案（同意 / 允许 / 温馨提示 / 隐私政策 / 我知道了…）时才去找关闭按钮，正常页面完全不碰
- **关闭按钮只认屏幕中部、且必须整词相等**：贴边的角标「×」一律排除；「取消」「关闭」不接受包含匹配，避免把「取消订单」「关闭自动续费」当成弹窗关掉
- **绝不再点屏幕最底部兜底**：找不到「我的」时，用识别到的底部标签行的真实 y 坐标点右下角；那一行都没有就直接判失败，不再盲点（屏幕最底部是系统导航栏，点下去会误触返回/主页把 App 顶掉）
- **同一坐标 1.5 秒内不重复点**，页面切换途中不会连点
- **已签到判定以按钮为准**：签到日历里历史日期也写着「已签到」，所以只要有「签到」按钮就点，没有按钮才判「今天已签到」


## 界面与打卡记录

- **今日状态卡**：顶部直接显示今天「已打卡成功 / 已完成（已签到）/ 打卡失败 / 还没打卡」，附执行时间、来源（定时任务、手动、重试）和连续打卡天数
- **开始打卡按钮**：不用等定时任务，随时点一下就手动执行一次；执行中按钮会显示「打卡执行中…」并禁用，避免重复触发
- **打卡记录列表**：最近 30 天逐条列出日期、时间、状态（成功 / 已签到 / 失败，颜色区分）、**连续第 N 天**、失败原因，以及**签到截图缩略图**（点开看大图），可一键清空
- **结果反馈**：执行结束时界面即时收到广播，成功弹 Toast、失败弹对话框（可「再试一次」或「查看日志」）
- **未打卡弹窗**：过了每日执行时刻还没打卡，打开 App 会自动弹窗，选项为「立即打卡 / 30 分钟后提醒 / 今天不再提醒」；同一天只弹一次
- **未打卡通知**：另设提醒时刻（默认 21:00），到点若今天仍未成功打卡就发高优先级通知，点通知直接进 App 并触发弹窗
- **连续打卡天数**：自动统计从今天（或昨天）往前连续成功的天数

## 首次使用

1. 安装 APK，打开应用
2. 依次点：
   - 去开启无障碍服务（设置 → 无障碍 → 滴滴充电自动签到 → 开启）
   - 加入电池优化白名单（否则国产 ROM 会杀后台）
   - 允许精确闹钟（Android 12+ 必须，否则只能走近似闹钟）
   - 允许通知
3. 设置执行时间、提醒时间与目标包名，点「保存配置并重新排程」
4. 点顶部「开始打卡」（或原来的手动测试按钮已合并到这里），看记录列表与「最近截图」确认能走到签到按钮

## 已知限制

- 屏幕若是密码锁屏，无障碍服务无法越过锁屏，需要关闭锁屏密码或用智能解锁；任务会记录在日志里
- 部分 ROM（MIUI / ColorOS / EMUI）需要在系统设置里额外允许「自启动」「后台弹出界面」
- OCR 识别的是当前屏上的文字：字号过小、被遮挡、低对比度（半透明浮层）可能漏识别；此时会退化为按控件文字识别
- 「车主 / 我的」这类图标入口如果没有文字，走 OCR 就找不到；「我的」有右下角坐标兜底，「车主」只能靠改关键词或补文字
- 截图能力需要 Android 11+（`takeScreenshot` 免授权），低版本自动降级为控件文字识别
- ML Kit 中文模型随 APK 打包，APK 体积会增加约 10~20MB，但运行时不联网

## 合规提示

自动化操作可能违反平台用户协议，存在被风控/封号风险；本项目仅用于个人单账号、低频使用，请勿批量多账号运行。

## 定时执行、唤醒与解锁（v1.5 起）

1. **排程**：每天基准 07:00，`+0~60` 分钟随机，落在 07:00~08:00 之间；用 `setExactAndAllowWhileIdle`（RTC_WAKEUP）排，Doze 下也能醒。运行结束、开机、应用打开都会重排下一天。
2. **点亮屏幕**：任务开始先 `SCREEN_BRIGHT_WAKE_LOCK + ACQUIRE_CAUSES_WAKEUP`，点亮屏幕并保持到任务结束。
3. **解锁**：检测到 `KeyguardManager.isKeyguardLocked()` 为真时，用无障碍服务在锁屏数字键盘上按密码逐位点击，再点「确定/✓」。
   - 能点通 → 直接继续走签到流程；
   - 系统禁止无障碍操作安全锁屏（部分机型会拒绝）→ 发一条「需要解锁手机」通知，任务原地等待（单轮上限 180 秒），你解锁后自动接着跑，不会从头再来。
   - 锁屏密码在 `Config`（SharedPreferences `checkin_cfg` 的 `pin` 项），默认 `688888`。
4. 想让早晨这一轮**完全无需人工**，最稳的做法是把锁屏改成「无密码/滑动」；保持 PIN 时能否自动输进去取决于机型的无障碍安全策略。

## 行为细节（v1.4 起）

- 动作之间固定 **1~2 秒随机停顿**，不呈现机械等距节奏
- **严格前台校验**：当前前台不是滴滴（也不是系统弹窗）时，只重新拉起滴滴，绝不在别的 App 页面上点击
- 系统「应用启动」确认框（"想要打开滴滴"）优先处理，点「始终打开」，绝不再点「取消」
- 会员中心底部有固定「立即续费」浮层，下滑手势起点必须避开（从 0.60H 起手，划到 0.24H）
- 识别到自己 App 的界面文字（今日打卡、去开启无障碍服务…）一律不点
## 保活（v1.5.2 起）

安卓会周期性清理后台，这里做了四层加固：

| 层 | 做法 | 作用 |
|---|---|---|
| 最近任务隐藏 | `MainActivity` 加 `android:excludeFromRecents="true"`，应用内也可勾选切换 | 「最近任务」里不出现卡片，系统一键清理/左滑都碰不到它，等于卡片被"锁"住 |
| 前台常驻服务 | `KeepAliveService`，`IMPORTANCE_MIN` 常驻通知 + `START_STICKY` + `stopWithTask=false` | 进程优先级提到最高档，最不容易被回收 |
| 被划掉自动重启 | `onTaskRemoved` → 5 秒后广播 `KeepAliveReceiver` 重新拉起 | 万一卡片还是被划掉，5 秒内自己回来 |
| 15 分钟心跳 | `KeepAliveJobService`（`setPeriodic(15min)` + `setPersisted(true)`） | 进程被杀后由系统定期拉起，并补齐每日闹钟与提醒 |

补充说明：

- 第三方 App **没有系统 API 能"锁定"最近任务卡片**（那是各厂商 ROM 的私有功能）。本方案的做法是**直接隐藏卡片**——卡片不存在，就不会被一键清理划掉，效果比锁定更彻底。
- 想改回"显示卡片自己手动锁定"：在应用首页取消勾选「在最近任务卡片中隐藏」，然后长按卡片点厂商的锁图标。
- 各厂商（MIUI / 澎湃 / ColorOS / OriginOS / 鸿蒙）还需要在系统设置里允许 **自启动 + 后台无限制**，否则以上都白搭。
